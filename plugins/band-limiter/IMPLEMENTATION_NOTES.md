# Craft Band Limiter family - implementation notes

Clean-room implementation of `spec/band-limiter/r1` (SPEC.md and `tables/*`). Four products, one engine, selected at
compile time with `CRAFT_VARIANT`:

| Product | Variant | Code | CLAP id | Latency (reported, all rates) |
|---|---|---|---|---|
| Craft Band Limiter | linear phase, full controls | `CBlm` | `com.craftaudio.band-limiter` | 3528 |
| Craft Band Limiter Profile | linear phase, 9 profiles | `CBlp` | `com.craftaudio.band-limiter-profile` | 3528 |
| Craft Band Limiter LL | low latency, full controls | `CBll` | `com.craftaudio.band-limiter-ll` | 64 |
| Craft Band Limiter LL Profile | low latency, 9 profiles | `CBlq` | `com.craftaudio.band-limiter-ll-profile` | 64 |

## Architecture

- `source/dsp/CrossoverTable.h`, `tests/SpecTables.h`: generated by `tools/generate_tables.py` from the spec CSVs.
- `source/dsp/BandSplitters.h`
  - `LinearPhaseSplitter`: overlap-save, FFT 8192, hop 512, FIR half length 2888 (delay 2888 + 512 = 3400, the other 128
    samples are the look-ahead). Kernels are designed from the table (columns interpolated in log2 of the crossover),
    truncated and made exactly real, so left/right travel as the real/imaginary part of one complex FFT. Bands telescope
    (`b1 = L1`, `b_k = L_k - L_(k-1)`, `b5 = x - L4`), so the sum is the delayed input exactly. One crossover is redesigned
    per hop and cross-faded over that hop, without allocation.
  - `LowLatencySplitter`: for each crossover a denominator `D(s)` (2nd order, Q < 0.707) gives `l = 1/D^2`,
    `A = D(-s)/D(s)`, `h = A - l`. `l/A` and `h/A` are real and non-negative and `l + h = A`; with compensation allpasses
    all bands share the phase `A1 A2 A3 A4`. TPT state-variable sections; frequency and Q per crossover are a fit to
    `xo_lowlatency_bands.csv` (residual at most 0.017, bilinear warping included at 44.1/48/96 kHz).
- `source/dsp/BandLimiterEngine.h`
  - Mixer: per-band sliding peak detectors and one for the sum. Only when the *actual* sum exceeds the threshold are
    targets computed: `g_b = min(1, lambda * w_b * d_b^(beta-1))` with `d_b = s*e_b + (1-s)*mean(e)`, water-filled so that
    `sum(g_b * e_b)` equals the budget (threshold scaled by the coherence `sum(e) / peak(sum)`, never below the threshold).
  - Fitted constants: `kappa = 0.82` (the unity clamp supplies the saturation of spec 6.2), `beta = 0.082`, a tilt of
    0.14 dB per dB of over per octave of release ratio around 10 dB over (spec 6.5), +1 dB on band 5 (five-tone rows).
  - Separation over-attenuation (spec 6.3, D1): measured curve 0 / 0.70 / 1.04 / 0.96 / 0 dB at 0..100 %, scaled by how
    concentrated the signal is, `(c / 0.278)^2.33`, `c = sum(e^2) / sum(e)^2`. This also yields the -16.6 dB of profile 3.
  - Release (`BandRelease`): after a lag, gain rises linearly in *linear gain* at a rate `1/T`,
    `T = 123.2 + 2.852 * R^0.8857` ms times a per-behaviour, per-band factor. Adaptive kinds charge with a 37 ms time
    constant during an over; the uncharged part of the depth decays with 4.5 ms. Manual has no adaptation, and a settling
    dip of 26 % of the depth (in dB) when an over has fully ended, which the burst table shows.
  - Box-smoothed look-ahead (LP 64, LL 32 samples), then a wideband stage of the same length (8 ms release) that guarantees
    the threshold on the real sum, then make-up and a final clamp to the ceiling.
  - Stereo is linked (one gain per band); mono runs one channel.
- Requantiser: `plugins/mastering-limiter/source/dsp/Requantiser.h` is included unchanged, so that plug-in is untouched.
- `source/ui`: original vector artwork. `LookAndFeel` and `Controls` are copies of the mastering limiter's helpers in this
  namespace; `BandDisplay` holds the gain/frequency display and the meters.

## Tests

`tests/` (Catch2, CTest prefix `band-limiter/`) check, against the generated tables and at 44.1/48/96 kHz where the spec
applies: LP kernels against every table point (+-0.02), LL magnitudes (+-0.03) and sum flatness (+-0.05 dB), latency, LP
bit-exact neutrality, static gain and make-up, the ceiling on noise/clicks/steps/tones, all two-tone and five-tone rows
(+-1 dB at 48 kHz, +-1.5 dB elsewhere), all step and burst release rows, profile map and rows, requantiser totals,
digital silence, word lengths, solo, mappings and out-of-order crossovers.

Output-peak rows are checked to +-0.35 dB (the spec states only "per section 5": never above the ceiling).

## Deviations from the normative tables

1. **LL release rows not reproduced.** `release_steps.csv` lists `LL_tstep1k*` with t63 = t90 = t99 = 1 ms for band-3
   releases of 10, 400 and 1000 ms. That contradicts spec 7 (the Release value scales recovery), 8 ("release as
   sections 5-7") and 12 (which gives the same 231/409/495 ms for "LP-Multi and LL-Multi"). The rows look like a measurement
   artefact, but this could not be verified. The LL engine uses the same release law as LP; no test asserts these rows.
   **Decision needed from the analyst side.**

## Questions / assumptions

- Profile control values are not in the spec; they were chosen to meet `profiles.csv` (see `dsp/Parameters.h`). Profiles keep
  the default crossovers. Profile 1 equals the Multi defaults.
- Fitted law constants are fits to the tables, not measured internals. Behaviour between measured points is unverified, e.g.
  Aggressive/Warm/Scaled after short bursts (no table rows): they use the Adaptive charge law.
- The Manual settling dip scales with depth; only 12 dB depth is measured. It also lowers the gain briefly after every
  finished over on programme material.
- Tones on the wideband stage: envelope attack 15 ms means the first ms of an onset are limited by the wideband stage, not
  the band mix, so very short overs (below about 15 ms) are close to wideband limiting. Not contradicted by the tables.
- Shaped requantiser totals are only specified at 48 kHz (mastering spec r2 7.2) and are tested at 44.1/48 kHz; at 96 kHz
  they are lower by design of the per-rate NTF (Ultra 2.84 against 3.93 LSB rms).
- Ceiling: exact before the requantiser. Rounding and shaping can exceed a non-full-scale ceiling by quantiser error; tested
  to 0.51 LSB at 24 bit without dither. Same order as the mastering limiter.
- Out-of-order crossovers are sorted (spec open question 3). Mono: same processing on one channel (D6). Above 96 kHz the LP
  latency stays 3528 samples, so the lowest crossovers become less accurate; not tested.
- CLAP ids follow the assignment rather than the `<slug>.<variant>` pattern of CONTRIBUTING.
- Spec 13's "master release offset" in the Multi layout is not implemented (no such parameter in spec 3); the band meter's
  relative-threshold marker is drawn as a band gain-reduction marker. **GUI appearance has not been reviewed visually.**

## Status

- Windows x64 (MSVC, Release): VST3, CLAP and Standalone of all four products build; 27/27 test cases pass in CTest.
- Linux x64: DSP tests pass (GCC, 27/27). The JUCE plug-in targets were not built on Linux locally (left to CI).
- `craft_hoststress --seconds 150 --editor` on each VST3: 0 failures. All four ran at once, so the sample counts are lower
  than a solo run would give.
- CPU, one instance, 48 kHz stereo while limiting (Linux, GCC -O2, DSP only): LP about 19 % of a core, LL about 5 %. LP is
  heavy and its FFT work comes in bursts every 512 samples; no optimisation has been attempted.
